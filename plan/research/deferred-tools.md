# Deferred tools and omp's xd:// device protocol

## Scope and source baseline

The omp source snapshot is current upstream `main` fetched for this research, pinned to **`f0200abf28e8d314125854600cf726dece495246`** ([commit](https://github.com/can1357/oh-my-pi/commit/f0200abf28e8d314125854600cf726dece495246)). The fetched commit metadata is dated 2026-11-10 02:14:50 +0100; this is the actual upstream snapshot returned, not an assumed release version. All omp source links below use this immutable commit. Other implementations use official documentation or separately pinned upstream source. Issue reports are identified as reports, not proof that a historical bug still exists. This was read-only source/document research; no axo files were changed and no behavior was experimentally tested.

**Bottom line:** `xd://` is an application-level virtual device bus over existing `read` and `write` tools, not MCP itself and not a provider-native deferred-tool API. It keeps selected tools out of the declared function list, but does **not** eliminate their catalog tokens, guarantee an entirely immutable system prompt, or create a separate permission boundary. Current default prompt docs are **catalog-only**, not the older builtins-inline default.

# Part 1 — omp in depth

## 1. What it is, implementation, and name

The protocol is documented directly in the header of [`packages/coding-agent/src/tools/xdev.ts:1-30`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/xdev.ts#L1-L30): `read xd://` lists mounted tools; `read xd://<tool>` retrieves documentation/schema; `write xd://<tool>` executes with a JSON argument object encoded in `content`. The same canonical tool instances back direct and device calls; mounting is presentation, not a second implementation of each tool.

Implementation ownership:

- **URL grammar:** [`packages/tui/src/tools/xd-url.ts:1-36`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/tui/src/tools/xd-url.ts#L1-L36). Bare root, a device name, and a separate two-component documentation-topic form are supported. Arbitrary path/query/fragment addressing is not a device-name grammar.
- **Scheme handler:** [`packages/coding-agent/src/internal-urls/xd-protocol.ts:55-135`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/internal-urls/xd-protocol.ts#L55-L135), `XdProtocolHandler`, registered as scheme `xd`. Its resource contract is `backing: "device"`, no selectors, immutable read view, compact transcript, handler-backed text writes in device scope. It routes ordinary tool devices and the exceptional resolution/QA devices.
- **Registry/state:** [`packages/coding-agent/src/tools/xdev.ts:232-283`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/xdev.ts#L232-L283), `XdevState`: canonical `Map<string, Tool>`, ordered mounted-name set, built-in-origin set, active-name predicate, optional execution permission decorator. The enabled dispatch union is **active direct tools plus mounted names**. Thus even a direct tool can be addressed through `xd://<name>`, although listings remain mounted-only.
- **Dispatch:** [`packages/coding-agent/src/tools/xdev.ts:422-506`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/xdev.ts#L422-L506).

**What does “xd” stand for?** No English expansion was found in the checked comments, docs, changelogs, or introducing commit message. Source calls it “virtual tool devices”; `xdev` is the identifier/config spelling. A UI acronym map renders `xdev` as “XDev”, not an expansion ([`packages/coding-agent/src/session/session-dump-format.ts:130-138`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/session/session-dump-format.ts#L130-L138)). Do not present “external device” or “extension device” as established etymology. The introducing commit is [`5ff277349cb1b1cda27cf1b3b4d946e160643906`](https://github.com/can1357/oh-my-pi/commit/5ff277349cb1b1cda27cf1b3b4d946e160643906), “refactor(coding-agent): consolidated tool surface onto xd:// devices and hub”, in the v17.0.0 history. It replaced the earlier BM25 discovery surface; this does not mean current pi upstream uses the same design.

## 2. Which tools are devices, and who decides?

There are two distinct decisions: **is a tool enabled?** and **how is it presented?** `xd://` controls the latter, not authorization by itself.

| Control | Current behavior |
|---|---|
| `tools.xdev` | Defaults **true**; when false, enabled tools are exposed directly. Restricted-tool construction can omit the bus entirely. |
| Tool `loadMode` | `essential` stays direct; `discoverable` is eligible to mount. Tool implementation/extension/custom definition supplies it; adapters apply defaults. |
| Hard pins | `read`, `write` can never mount because they carry the bus. `todo`, `yield`, `ask`, `grep`, `web_search` remain direct despite discoverability, for harness/UX/model expectations. |
| `tools.xdevDocs` | **catalog** default; `inline` includes docs/types when within budget; `builtins` includes built-in docs/types and catalogs dynamic tools. This does not promote a device to a direct function. |
| `tools.xdevInlineDevices` | Name/glob allowlist for dynamic docs in `builtins` mode; ignored in `catalog`. Again a docs setting, not execution exposure. |
| `tools.xdevNotices` | UI mount/unmount chatter, default true. Disabling it does **not** stop the model learning changes at its next prompt. |

Sources: [`packages/coding-agent/src/tools/settings.ts:1013-1072`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/settings.ts#L1013-L1072); predicate/pins [`packages/coding-agent/src/tools/xdev.ts:48-88`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/xdev.ts#L48-L88); construction gate and synthetic transport [`packages/coding-agent/src/tools/index.ts:902-944`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/index.ts#L902-L944).

Default adapter policy preserves essential built-in names when an extension re-registers them, otherwise a novel tool defaults to discoverable ([`packages/coding-agent/src/tools/essential-tools.ts:22-48`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/essential-tools.ts#L22-L48); [`packages/coding-agent/src/extensibility/custom-tools/wrapper.ts:20-30`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/extensibility/custom-tools/wrapper.ts#L20-L30)). MCP tools implement the custom-tool interface and take that adapter path ([`packages/coding-agent/src/mcp/tool-bridge.ts:729-771`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/mcp/tool-bridge.ts#L729-L771)). Therefore **MCP is normally mounted under the default xdev setup, but “MCP always becomes devices” is false**: global disabling/restricted construction and the active presentation rules matter. This is not pi's five-valued `exposure` API.

The built-in discoverables that can mount include `ast_grep`, `ast_edit`, `debug`, `ida`, `github`, `lsp`, `checkpoint`, `rewind`, `security_scan`, `memory_edit`, `retain`, `recall`, and `reflect`, subject to enablement/environment. Factory inventory is [`packages/coding-agent/src/tools/index.ts:590-633`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/index.ts#L590-L633); examples of the declared flag are [`packages/coding-agent/src/tools/ast-edit.ts:230-245`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/ast-edit.ts#L230-L245), [`packages/coding-agent/src/lsp/tool.ts:190-202`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/lsp/tool.ts#L190-L202), [`packages/coding-agent/src/tools/checkpoint.ts:55-102`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/checkpoint.ts#L55-L102). This is a conditional set, not a promise every session has every endpoint.

## 3. Discovery and exact documentation delivery

The base system prompt template says:

> # xd:// Tool Devices
> Write JSON args as `content` to `xd://<tool>` via `{{toolRefs.write}}`. Invalid args return schema in error → fix/retry.

It then inserts `{{xdevDocs}}` ([`packages/coding-agent/src/prompts/system/system-prompt.md:84-88`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/prompts/system/system-prompt.md#L84-L88)). Catalog-only devices appear under **“Additional devices (docs on demand)”**, one name and summary each, followed by “Read xd://<tool> for full docs + JSON schema before first use.” Separate MCP route guidance maps original MCP tool names to actual device paths; its bounded projection can omit a tail and tells the model to inspect `xd://` for exact paths ([`packages/coding-agent/src/prompts/system/mcp-xdev-guidance.md:1-15`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/prompts/system/mcp-xdev-guidance.md#L1-L15)).

**Bare read:** `read({path:"xd://"})` returns a count, one mounted `xd://name summary` row per device, and read/write guidance. It is mounted-only; special resolver/QA endpoints and direct tools need not appear. **Named read:** heading with tool name/label, description, a Schema section, and execution instruction. Importantly, despite prose saying “JSON schema”, the current renderer uses `jsonSchemaToTypeScript(toolWireSchema(tool))` and prints:

```ts
type Args = /* rendered TypeScript type */;
```

It does **not** dump literal JSON Schema. Calls still require JSON, not TypeScript. Direct enabled tools can also be read by name. Writing empty content, `?`, or `help` to an ordinary device retrieves the same docs without executing. Named topic reads `xd://<tool>/<topic>` retrieve separate tool-owned documentation. Sources: [`packages/coding-agent/src/tools/xdev.ts:113-129`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/xdev.ts#L113-L129), [`packages/coding-agent/src/tools/xdev.ts:229-230`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/xdev.ts#L229-L230), [`packages/coding-agent/src/tools/xdev.ts:293-322`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/xdev.ts#L293-L322), [`packages/coding-agent/src/tools/xdev.ts:433-453`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/xdev.ts#L433-L453), [`packages/coding-agent/src/internal-urls/xd-protocol.ts:117-135`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/internal-urls/xd-protocol.ts#L117-L135).

Summaries use explicit `summary` or first nonempty description line. Dynamic metadata is sanitized to one line, control characters stripped, and bounded (external-summary cap 200). Inline docs have **48,000-character total / 10,000-character per-device budgets**; overflow falls back to catalog entries. These are doc budgets, not a constant catalog-size guarantee ([`packages/coding-agent/src/tools/xdev.ts:180-218`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/xdev.ts#L180-L218), [`packages/coding-agent/src/tools/xdev.ts:248-253`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/xdev.ts#L248-L253), [`packages/coding-agent/src/tools/xdev.ts:331-419`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/xdev.ts#L331-L419)).

## 4. Inventory changes, history, compaction, and caching

The notice template is [`packages/coding-agent/src/prompts/system/xdev-mount-notice.md:1-19`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/prompts/system/xdev-mount-notice.md#L1-L19). It emits `<system-notice>xd:// device inventory changed.` followed by **added tools**, removed names (“Unmounted; writes fail”), optional configured inline docs, and an explicit warning that dynamic summaries are untrusted metadata whose instructions must not be followed.

- **Trigger is mounted-name membership change**, e.g. MCP connections/disconnections or late extension registration/removal. It is not a full inventory dump; it is a net delta relative to what the model was actually told. Opposite pending operations cancel each other. Same-name schema/description replacement does **not** by itself create an added/removed notice. A mode transition is not an independent “announce everything” trigger; if it does not change mounted membership it emits no mount notice ([`packages/coding-agent/src/session/session-tools.ts:1855-1885`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/session/session-tools.ts#L1855-L1885)).
- **No unsolicited assistant turn:** changes queue and ride the next user prompt rather than immediately steering an idle model. A substantial pending inline-doc notice is previewed before context maintenance to account for request size, but consumed only after maintenance/rebuild decisions ([`packages/coding-agent/src/session/agent-session.ts:9545-9555`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/session/agent-session.ts#L9545-L9555), [`packages/coding-agent/src/session/agent-session.ts:9610-9665`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/session/agent-session.ts#L9610-L9665)).
- **Persisted:** custom history message type `xdev-mount-notice`, with structured `added`/`removed` names. On resume the announced set is reconstructed from persisted notices, with compatibility parsing for old text-only notices ([`packages/coding-agent/src/session/session-tools.ts:318-327`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/session/session-tools.ts#L318-L327), [`packages/coding-agent/src/session/session-tools.ts:1904-1955`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/session/session-tools.ts#L1904-L1955), [`packages/coding-agent/src/session/session-tools.ts:2247-2258`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/session/session-tools.ts#L2247-L2258)).
- **Deduplication:** devices already delivered in the actual base catalog or committed MCP route guidance are suppressed; reconnecting an already-known name is not re-announced. Comments explicitly cite avoiding redundant developer messages that bust the provider's prompt-cache prefix ([`packages/coding-agent/src/session/session-tools.ts:2192-2238`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/session/session-tools.ts#L2192-L2238)).
- **Compaction is not unconditional re-announcement.** In a live session the in-memory announced set survives compaction; older notices may be summarized out. Resume seeds from surviving history and current base/route delivery. A base rebuild can absorb pending additions. There is no “always resend the entire inventory after compaction” mechanism in this path. Discovery remains recoverable via the root listing. The reset operation and navigation call site are [`packages/coding-agent/src/session/session-tools.ts:1899-1908`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/session/session-tools.ts#L1899-L1908) and [`packages/coding-agent/src/session/agent-session.ts:8194-8204`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/session/agent-session.ts#L8194-L8204). This distinction matters if axo promises stronger post-compaction rediscovery invariants.

**Cache conclusion:** a stable native function surface avoids one common prefix-change cause; append-only, deduplicated notices address another. But catalog/doc rendering, mode/prompt rebuilds, same-name definition changes, and provider behavior remain separate concerns. “No schema duplication” in the xdev header is not “zero schema tokens”: inline mode deliberately ships types in prompt text ([`packages/coding-agent/src/tools/xdev.ts:12-25`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/xdev.ts#L12-L25)).

## 5. Invocation, validation, results, and asynchronous work

Concrete ordinary-device call:

```js
write({ path: "xd://github", content: JSON.stringify({ op: "file_read", repo: "owner/repo", path: "README.md" }), i: "Reading repository README" })
```

The outer tool's JSON has a **string** `content` containing another JSON object. The literal device URI goes in **`write.path`**; it is not an implicit tool selector. A model emitting the call as JSON must escape embedded quotes/newlines accordingly.

Pipeline: `WriteTool.execute → internal URL router → XdProtocolHandler.write → dispatchXdevTool → canonical/decorated tool.execute`. Ordinary device writes require the write-tool call context. Bare-root writes fail with listing guidance. Handler result content, error flag, and usefulness are returned as the **outer write tool's result**, with `details.xdev` metadata ([`packages/coding-agent/src/internal-urls/xd-protocol.ts:78-114`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/internal-urls/xd-protocol.ts#L78-L114), [`packages/coding-agent/src/tools/write.ts:950-1045`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/write.ts#L950-L1045)).

Validation ([`packages/coding-agent/src/tools/xdev.ts:145-177`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/xdev.ts#L145-L177)):

1. Strict `JSON.parse(content)`; null, arrays, primitives are rejected because args must be an object.
2. Habitual top-level `i` is stripped unless the inner wire schema declares it.
3. Shared `validateAgentToolArguments(...,"payload")` runs against the inner wire schema, rather than trusting write's string schema.
4. **Malformed JSON:** brief error “xd://name expects a JSON args object as content (...). Write `?` for docs.” **Non-object:** brief object-required error. Neither automatically includes the whole schema.
5. **Valid JSON / schema mismatch:** error “Invalid args for xd://name: ...” plus full rendered docs/type for repair. Thus the prompt's “invalid args return schema” slogan has a narrower actual implementation.
6. Tools with `lenientArgValidation` retain the shared raw-argument fallback for schema mismatch, not malformed JSON; forged parse-error sentinel fields are removed ([`packages/agent/src/tool-arguments.ts:22-50`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/agent/src/tool-arguments.ts#L22-L50)).

**Progress and multimodal output:** partial `onUpdate` content/error state is forwarded, wrapping details in `{xdev:{tool,mode,args,tier,inner}}`; final text/image blocks are preserved. UI delegation uses the inner tool renderer. The write renderer waits to know the path before rendering a file-write preview, avoiding false previews for device calls ([`packages/coding-agent/src/tools/xdev.ts:27-30`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/xdev.ts#L27-L30), [`packages/coding-agent/src/tools/xdev.ts:465-505`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/xdev.ts#L465-L505)).

**Long running/async:** xdev itself has no background queue or resumable execution scheduler. It awaits the inner promise, forwards the abort signal, and rethrows cancellation. Background jobs/services belong to the invoked tool's own implementation. Other execution exceptions become an error write result with rendered error text. An `async` parameter works only if that particular tool owns such a parameter; the scheme adds no universal async contract ([`packages/coding-agent/src/tools/xdev.ts:479-505`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/xdev.ts#L479-L505)).

## 6. Policy, hooks, replay, subagents, and eval

**Approval is device-aware.** Before executing, the outer write tier resolver parses the inner object and evaluates the target's argument-dependent approval tier. It returns `policyKey: deviceName`, checking `tools.approval.<device>` before generic write policy. Unknown/malformed/non-object targets or throwing approval functions fail closed to `exec`; special resolution devices are read-tier, issue reporter write-tier ([`packages/coding-agent/src/internal-urls/xd-protocol.ts:24-52`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/internal-urls/xd-protocol.ts#L24-L52)). The inner execution receives `xdevPolicyKey` so the same unchanged call does not prompt twice. Denies and provider safety checks remain enforced, and hook-rewritten effective input is re-evaluated ([`packages/coding-agent/src/extensibility/extensions/wrapper.ts:265-325`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/extensibility/extensions/wrapper.ts#L265-L325), [`packages/coding-agent/src/extensibility/extensions/wrapper.ts:380-408`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/extensibility/extensions/wrapper.ts#L380-L408)).

**Current extension hooks see BOTH layers, not just write.** Canonical tools are wrapper instances ([`packages/coding-agent/src/sdk.ts:3892-3894`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/sdk.ts#L3892-L3894)). The wrapper explicitly emits `tool_call` for nested xd dispatches the agent loop did not already emit, with the **inner name and decoded args**; handlers can block/rewrite. Both inner and outer executions emit `tool_result`, the outer carrying `details.xdev` ([`packages/coding-agent/src/extensibility/extensions/wrapper.ts:252-325`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/extensibility/extensions/wrapper.ts#L252-L325), [`packages/coding-agent/src/extensibility/extensions/wrapper.ts:534-548`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/extensibility/extensions/wrapper.ts#L534-L548)). This is materially different from the historical [#6105 report](https://github.com/can1357/oh-my-pi/issues/6105), which correctly described its then-current unwrapped inner dispatch. Do not use that issue as the current behavior specification.

**History/recovery:** normal provider history records an ordinary `write` call/result; the decoded inner call is not a second provider-native call. Malformed model calls that use `xd://name` as a function name have fallback resolution, with canonical name rewriting before replay ([`packages/agent/src/agent-loop.ts:3156-3162`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/agent/src/agent-loop.ts#L3156-L3162)). Parked child initialization persists mounted names and cold revival restores the partition ([`packages/coding-agent/src/task/executor.ts:5211-5215`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/task/executor.ts#L5211-L5215), [`packages/coding-agent/src/task/persisted-revive.ts:474-475`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/task/persisted-revive.ts#L474-L475)). This is restoration of session/tool presentation, **not an exactly-once side-effect guarantee**; no xdev execution journal/deduplication transaction was found in dispatch.

**Subagents can use devices.** Normal child creation keeps MCP/extensions enabled unless explicitly restricted. An explicit read-without-write tool list can receive synthetic `deviceOnlyWrite`: non-device host filesystem writes are refused, but device execution and local scratch are allowed. Therefore **“read-only” frontmatter is not a closed capability grant**; mounted MCP/extension operations can still mutate external state. ## 8. Observed downsides and history, distinguished from current bugs

- **Double serialization/protocol learning:** [#10450](https://github.com/can1357/oh-my-pi/issues/10450) reports systematic missing `write.path` on first invocation; the convention names `content` but not the path slot. It gives failing/succeeding calls and proposes explicit parameter binding/example. Current template still uses that convention. This is a user-reported observation, not a measured failure rate across all models.
- **Definitions moved, not removed:** [#6063](https://github.com/can1357/oh-my-pi/issues/6063) showed historical full docs/types reinlined into the system prompt. It was addressed by docs modes in [#6395](https://github.com/can1357/oh-my-pi/pull/6395) / [77669aed5401](https://github.com/can1357/oh-my-pi/commit/77669aed5401); that release used builtins default. **The current pinned setting is catalog default.** Inline mode still intentionally incurs those costs.
- **Escaping/JSON correctness:** strict inner JSON parsing creates a second syntax boundary; valid outer write JSON does not guarantee valid device args. The implementation supplies error repair (§5). No separately verified issue quantifying generic JSON escaping failures was found; do not conflate malformed JSON with the missing-path issue. TypeScript schema presentation versus JSON payload format is an additional [INFERENCE] confusion risk.
- **Special-path contract confusion:** [#6569](https://github.com/can1357/oh-my-pi/issues/6569) includes a later detailed report where the model sent full Markdown to propose instead of creating the local plan artifact/submitting its slug, and stale plan fallback reported success. This is a historical issue report, not a claim that the exact fail-open behavior still exists at the pin.
- **Outer/inner semantics are easy to lose:** historical [#5727](https://github.com/can1357/oh-my-pi/issues/5727) / [#5729](https://github.com/can1357/oh-my-pi/pull/5729) missed argument-dependent device approval; current resolver fixes that. [#6105](https://github.com/can1357/oh-my-pi/issues/6105) documents historical hook invisibility, now superseded by the current wrapped inner dispatch.
- **Transport must remain available:** [#5764](https://github.com/can1357/oh-my-pi/issues/5764) reported an extension re-registering essentials as discoverable, removing read/write and stranding devices. Current hard pins and essential-name defaults address that root cause.
- **Training expectations:** code explicitly pins web_search because models call it directly without understanding the proprietary bus ([`packages/coding-agent/src/tools/xdev.ts:48-64`](https://github.com/can1357/oh-my-pi/blob/f0200abf28e8d314125854600cf726dece495246/packages/coding-agent/src/tools/xdev.ts#L48-L64)). Recovery fallbacks handle model-emitted device names as native function names, but this adds host machinery.
- **Dynamic metadata is a trust boundary:** current summaries are sanitized/bounded and notices mark them untrusted. That reduces presentation hazards; it does not make third-party tool descriptions trustworthy instructions.

## Primary sources and implementation-specific details

### [A] Anthropic API search

[Official tool-search docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool), sections **How tool search works**, **Custom tool search implementation**, and **Prompt caching**. The official types are `tool_search_tool_regex_20251119` and `tool_search_tool_bm25_20251119`. At least one tool stays nondeferred. The backend searches the supplied definitions and returns `tool_reference` blocks, then expands them; this is native tool deferral, not passing an untyped JSON string to write. A client-side search can return tool references in tool results. Deferred client-tool definitions are still supplied in the request catalog; deferred context is not deferred wire transmission. This is also different from lazy MCP *connection* startup.

### [B] Anthropic tool_addition/tool_removal

[Official Anthropic skills guidance, Mid-conversation tool changes](https://github.com/anthropics/skills/blob/main/skills/claude-api/shared/tool-use-concepts.md#mid-conversation-tool-changes-beta) documents beta header `mid-conversation-tool-changes-2026-07-01`, restricted model/platform availability, and this shape:

```json
{"role":"system","content":[{"type":"tool_addition","tool":{"type":"tool_reference","name":"get_forecast"}}]}
```

A tool to be added must already be declared in `tools[]` with `defer_loading:true`. Removal similarly uses `tool_removal`; changing a definition requires the documented two-request remove/update sequence. This is **not** arbitrary full new schema embedded directly in the addition block. The guidance is official but beta and model-specific; don't infer portability to every Anthropic-serving endpoint.

### [C] Claude Code

[Official MCP docs — Scale with MCP tool search](https://code.claude.com/docs/en/mcp#scale-with-mcp-tool-search) and [official Agent SDK tool-search docs](https://code.claude.com/docs/en/agent-sdk/tool-search). Current official default is **enabled**, not always the older auto-at-10% behavior. `ENABLE_TOOL_SEARCH`: unset/true defer by default (supported deployments); `auto` activates at 10% deferred-definition/context ratio; `auto:N` custom threshold; false eager. Some models/platform deployments fall back eager. Tool-search deny or omission from `--tools` causes eager loading; server config and tool `_meta["anthropic/alwaysLoad"]` can exempt tools. The SDK says up to five relevant tools load by default and remain until compaction of discovery messages, after which search can occur again. MCP docs document per-tool approval and normal SDK `canUseTool` handling. These published docs supersede third-party reverse-engineered default/compaction assertions.

### [D] OpenAI Responses

[Official tool-search guide](https://developers.openai.com/api/docs/guides/tools-tool-search): supported in gpt-5.4 and later; supports hosted `execution:"server"` and custom client-executed discovery. Hosted search emits `tool_search_call` and `tool_search_output`; client execution supplies matching output by call_id with selected definitions. Namespace names/descriptions remain visible while function details defer. The docs explicitly say all loaded tools are placed at the end of context, preserving earlier cache. [Official MCP tool guide](https://developers.openai.com/api/docs/guides/tools-remote-mcp) describes connector calls/approval; this is a separate policy layer.

### [E] Codex

[Official Codex PR #29486](https://github.com/openai/codex/pull/29486), “Use tool search for MCP tools by default”, establishes deferring effective MCP tools when tool_search and namespaces are supported and eager exposure otherwise. # Design lessons for axo

1. **Keep one canonical tool identity and execution path.** Device URL, native function, eval bridge, hooks, approval, audit record, and result renderer should resolve to that identity. Transport is not authorization; restrict code/subagent capability sets explicitly.
2. **Separate three knobs conceptually:** enabled/callable capability, model presentation (direct/deferred/code), and documentation placement. omp loadMode+xdevDocs and pi exposure show why conflating them creates surprising security/UX behavior.
3. **Make the invocation contract unambiguous.** Name `write.path` and `write.content`, show a correct JSON-escaping example, and distinguish plain-text special endpoints from ordinary JSON devices. Consider whether one typed generic call surface buys enough simplicity to avoid nested JSON; that is a design choice, not required to copy omp.
4. **Catalog-only must truly mean catalog-only.** Count prompt text/types as well as native schemas. A one-line catalog still grows O(number of devices); bounded namespaces/search or server grouping address a larger scale than moving all names into prose.
5. **Journal availability changes at prompt boundaries.** Coalesce deltas, avoid unsolicited model turns, persist announced state, and define same-name schema changes and post-compaction rediscovery deliberately. Freeze the callable snapshot offered to each turn. Do not treat live catalog membership as a sufficient grant.
6. **Preserve policy visibility through every bridge.** Inner name/validated args, hook rewrite/revalidation, cancellation, images/progress, and per-tool denial should be first-class. Distinguish one approved outer transport from multiple side-effecting inner actions. Exactly-once/replay safety requires an explicit durable design, not a URI scheme.
7. **Offer provider-native deferral as an adapter optimization, not the only semantic contract.** Anthropic/OpenAI preserve schemas and calls natively; portable xdev/files/code discovery works across more backends. Keep those presentation strategies interchangeable only if they preserve the same policy and journal behavior.
